STEP 4 — BUILD THE LLM WIKI (Knowledge Base)
================================================================

Create a structured knowledge base your agent will use.

  File: /wiki/llm_wiki.py

  Structure:
    - Load product_knowledge.jsonl
    - Chunk into 200–400 token passages
    - Create embeddings using Claude or sentence-transformers
    - Store in a vector store (ChromaDB or simple FAISS)

  Functions to implement:
    search_wiki(query: str, top_k: int = 5) -> list[dict]
      - Embeds query
      - Returns top_k most relevant passages

  Simple alternative (no embeddings):
    - Use BM25 keyword search (rank_bm25 library)
    - Faster to build, good enough for demo

================================================================
STEP 5 — BUILD THE INTENT ROUTER
================================================================

Classify every incoming query into one of these intents:

  Intent Categories (customize to your domain):
    - PRODUCT_FAQ       → "What does feature X do?"
    - TROUBLESHOOT      → "I'm getting error Y"
    - ACCOUNT_QUERY     → "How do I reset my password?"
    - GENERAL_CHAT      → "Hello, how are you?"
    - ESCALATE          → "I need to speak to a human"
    - OUT_OF_SCOPE      → Anything unrelated

  File: /router/intent_router.py

  Implementation approach:
    Option A (LLM-based):
      prompt = f"""
      Classify this query into one of:
      [PRODUCT_FAQ, TROUBLESHOOT, ACCOUNT_QUERY,
       GENERAL_CHAT, ESCALATE, OUT_OF_SCOPE]

      Query: {user_query}
      Reply with ONLY the category name.
      """
      response = claude.messages.create(...)

    Option B (keyword-based, faster):
      rules = {
        "TROUBLESHOOT": ["error", "issue", "broken", "not working"],
        "ESCALATE": ["human", "agent", "manager", "speak to"],
        ...
      }

  Return: { "intent": "PRODUCT_FAQ", "confidence": 0.92 }

================================================================
STEP 6 — BUILD THE CONTEXT WINDOW
================================================================

Construct the optimal context to send to Claude for each query.

  File: /context/context_builder.py

  Function: build_context(user_query, intent, user_id) -> str

  Context layers to include:
    1. System prompt (role + behavior rules)
    2. Relevant wiki passages (from Step 4 search)
    3. Last 5 conversation turns (from chat history)
    4. User preferences (tone, language, format)
    5. Current user query

  Token budget management:
    - Max context: 8000 tokens (leave 2000 for response)
    - Priority order: system > preferences > wiki > history > query
    - Truncate history first if over budget

  Use tiktoken or Claude's token counter to measure:
    import anthropic
    client = anthropic.Anthropic()
    token_count = client.beta.messages.count_tokens(...)

================================================================
STEP 7 — BUILD THE CONFIDENCE PREDICTOR
================================================================

Score how confident the agent is in its response.

  File: /confidence/predictor.py

  Signals to use:
    Signal 1 — Wiki retrieval score
      (cosine similarity of top result: 0.0 to 1.0)

    Signal 2 — Intent confidence
      (from intent router: 0.0 to 1.0)

    Signal 3 — Response self-assessment (LLM-graded)
      Ask Claude: "On a scale of 1-10, how confident are you
      in the above answer? Reply with only a number."

    Signal 4 — Query coverage
      (Did wiki passages cover the query keywords?)

  Final score formula:
    confidence = 0.4 * wiki_score
               + 0.3 * intent_confidence
               + 0.2 * llm_self_score
               + 0.1 * coverage_score

  Thresholds:
    >= 0.75 → HIGH confidence  → Answer directly
    0.50–0.74 → MEDIUM        → Answer with disclaimer
    < 0.50  → LOW             → Escalate or ask clarifying question

================================================================
STEP 8 — BUILD THE ROUTING LOGIC
================================================================

Wire everything together in main routing logic.

  File: /router/main_router.py

  Flow:
    1. Receive user_query + user_id
    2. Run intent_router → get intent
    3. Build context via context_builder
    4. Call Claude API → get response
    5. Run confidence_predictor → get score
    6. Apply routing rules:
       - intent == ESCALATE → return "Connecting to human agent..."
       - intent == OUT_OF_SCOPE → return "I can only help with X"
       - confidence < 0.50 → return clarifying question
       - confidence >= 0.50 → return Claude's response
    7. Log everything: query, intent, confidence, response, latency

  Logging schema (store in logs/query_log.jsonl):
    {
      "timestamp": "...",
      "user_id": "...",
      "query": "...",
      "intent": "...",
      "intent_confidence": 0.92,
      "wiki_score": 0.85,
      "final_confidence": 0.88,
      "response": "...",
      "latency_ms": 1240,
      "tokens_used": 850
    }

STEP 12 — PERFORMANCE ANALYSIS (For PDF Report)
================================================================

Run these tests and record results for your report:

  Accuracy Test:
    - Create 20 test queries with known correct answers
    - Run through agent, grade responses manually (correct/incorrect)
    - Accuracy = correct_count / 20

  Speed Test:
    - Measure latency for 20 queries
    - Calculate: avg, min, max, p95 latency

  Cost Test:
    - Log token usage per query (from Claude API response)
    - Calculate: avg tokens per query × Claude pricing
    - Claude Sonnet 4.6 pricing:
        Input: $3 per million tokens
        Output: $15 per million tokens

  Hallucination Rate:
    - For queries where wiki had NO relevant content,
      did the agent still give a confident answer?
    - Flag these as potential hallucinations

  Dashboard metrics to show:
    - Total queries handled
    - Average confidence score
    - Intent distribution (pie chart)
    - Latency over time (line chart)
    - Confidence distribution (histogram)
